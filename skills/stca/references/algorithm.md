# STCA 算法与调用约定

按锁定版本的上游实现调用 STCA；不要在适配器中重新实现相关性计算、排名或选优。源码依据见 [provenance.md](provenance.md)。

## 1. 输入与表示

- 保留原始 SMILES；原 STCA 完整输入流程按作者确认的 H-cap 契约，将末端连接点换氢后生成 MACCS。用 `prepare_hcap.py` 显式生成新列及处理记录，再传入原核心。作者档案中的 7,291 条 Tg 和 863 条 EC 已无 `*`，无需再次改写；863 条 EC 的 167 位均已与原始指纹表逐位核对一致。自定义模型沿用其训练表示；已有二值矩阵不做 H-cap。
- 对 SMILES 使用上游 `maccs_from_smiles`：RDKit MACCS 共 167 个位置，K0 是空位，K1–K166 保留原编号。不要改成 166 列后重新编号，也不要替换成 110 类、Morgan、Core8 或配方编码。
- 上游 `maccs_from_smiles` 本身不执行 H-cap，它只处理传入的已准备 SMILES；这不是否定上游之前的预处理。适配层的 H-cap 仅处理末端单键通配原子，内部或多键通配原子应报错。不要生成低聚物、去盐或做互变异构归一。原始与 H-cap canonical 图分别保留；H-cap 碰撞不证明完整聚合物相同，也不是外推距离。
- 无效结构必须保留为错误或明确失败。上游错误行的特征是 -1，不能用全零替代，否则缺失型规则可能错误放行。
- 训练/评价同时检查材料 ID、重复单元结构和条件；不同 ID 不能自动证明结构独立。上游 `train-profile --group-column` 会使用给定 ID 作为分组，适配器仍应检查 canonical SMILES 的重复。
- 适配层的 CSV 读取器逐记录检查字段数并保留所有文本（含 `001` 等前导零 ID）。运行时只替换上游 CLI 的 CSV 读取边界并在调用后恢复，计算与规则选择仍由锁定源码执行。未经该适配层建立的旧模型可能已把 ID 数值化；不要猜测修复其分组哈希，应从原输入重新训练并审计。

## 2. 阈值扫描与排名

对高方向直接扫描，令 `s = y`；对低方向直接扫描，令 `s = -y`。每个阈值 t 保留 `s >= t` 的样本，对第 j 个二值特征计算该子集中的出现频率。STCA 计算的是 **阈值 t 与该频率轨迹的 Pearson 相关性**，不是单个二分类目标与 bit 的相关性。

默认 value 网格从 `floor(min(s)/step)*step` 扫描到 `ceil(max(s)/step)*step`，仅保留有足够样本的点；至少需要 4 个有效阈值。上游排序后用反向累积特征计数计算频率。`unique`、`quantile` 是显式替代模式；不要自动替换原 value 网格。记录网格截断及最小子集大小。

剔除全源数据恒定的特征。正相关按相关系数降序，负相关按绝对相关系数降序，平局按 key 编号升序。默认名义 p 阈值为 0.05；`legacy_both_signs` 仅在通过名义筛选的特征仍包含正负两类时应用该筛选，否则保留未经过该筛选的非恒定表。这是嵌套阈值子集的历史筛选规则，不能解释为独立样本的显著性或因果检验。

## 3. 排名前缀与规则家族

取正榜前 a 个 bit，要求全部为 1；取负榜前 b 个 bit，要求全部为 0。两部分通过 AND 连接。保留纯正、纯负和正负混合前缀；不要允许跳过中间排名、改成任意组合/beam 搜索、OR 或投票。

正负可用深度分别为 p、q 时，完整前缀池包含 `p + q + p*q` 条规则。Tg 最大深度各 10 时是 120 条。

- 通用/Tg 家族：按源数据 F1 降序、规则名升序，先保留纯正、纯负、混合各自的最佳成员，再按同一排序填满家族；默认最多 8 条。
- EC 的 `paper`/`source_locked`：使用已打包的 V15 前缀长度模板。模板保存前缀深度与顺序，新数据重新学习 bit 排名；不得直接注入旧的获胜 bit。低 EC 的各 tier 家族大小为 6、6、6、7；高 EC 均为 8。
- 新数据排名深度不足时，上游默认报错；不要悄悄截短模板或切换 `generic`。

## 4. 档位、选优与协议

每个 tier q 的源数据真实目标：高方向用 `y >= quantile(y, 1-q)`；低方向用 `y <= quantile(y, q)`。分位数使用线性插值，边界包含相等值。并列值可使真实正例比例超过 q；q 也不控制新候选中最终选中的比例。

`AS = (MCC + precision + F1) / 3`。有效规则要求两类目标都存在、选择数达到配置支持数、precision 高于目标流行率，并满足 MCC 条件。默认支持数是 1；普通/Tg 要求 MCC > 0，EC 接受 MCC >= -1e-12。少于 20 个类别样本是诊断标记，不可默认为新增拒绝条件。

| 协议 | 家族 | 代表规则选择 | 数据含义 |
|---|---|---|---|
| `paper` | Tg 源 F1 家族；EC V15 模板 | 源/显式 selection/合并集 AS 的严格调和均值 | 历史结果重建；selection 标签参与选优 |
| `source_locked` | 同一对应任务家族 | 源数据有效 AS 最大值 | 新数据源内选规则，再冻结外评 |
| `generic` | 完整前缀池的源 F1 家族 | 源数据有效 AS 最大值 | 明确的通用探索协议，不能冒充 EC 主分析家族 |
| `legacy_snapshot` | 旧 SI 静态规则 | 已保存规则 | 只加载，无完整训练配方或数值训练阈值 |

`load_pretrained` 和 `STCA.for_profile` 默认是 `paper`。`paper` 训练必须显式给 selection 数据并设置 `acknowledge_selection_labels=True`；这是程序的数据角色声明。`source_locked` 拒绝 selection 数据。不要把缺失 selection 数据当作自动改协议的理由。无有效家族成员时保留无规则状态及诊断，不自动放松规则。

## 5. 任务预设与单位

| Profile | 存储目标 | 扫描 | 步长 | Tier |
|---|---|---|---:|---|
| `tg-high` | 摄氏度 `degC` | 正向 | 1.0 | 0.30、0.20、0.10 |
| `ec-low` | `log10(S/cm)` | 反向 `-y` | 0.01 | 0.20、0.15、0.10、0.05 |
| `ec-high` | `log10(S/cm)` | 同一反向扫描；交换正负榜一次 | 0.01 | 0.20、0.15、0.10、0.05 |

EC 高方向交换榜后仍执行正榜 bit=1、负榜 bit=0；不要再次翻转字面条件。使用 `ec_to_log10_s_cm(values, unit)` 转换四种明确单位：`S/cm`、`S/m`、`log10(S/cm)`、`log10(S/m)`。从 S/m 转为存储目标是 `log10(value)-2`；从 log10(S/m) 转换是减 2。原始电导率必须 >0，禁止猜单位或二次取对数。

`train-profile --tg-unit K` 会减 273.15；直接 Python 训练 Tg 时应先显式转换到 degC。没有预置 TC、Tm、Td、介电常数模型。使用自有对应数据训练时必须记录单独的目标、单位与扫描配置。

## 6. 冻结筛选、评价与输出解释

- `screen(smiles, tier=..., errors=...)` / `screen_fingerprints(...)` 只应用冻结规则。输出 selected、规则名、缺少的必需 bit、出现的禁止 bit 等；selected 是结构规则匹配，不是性能预测值、概率或实验达标证明。
- `evaluate(..., cutoff_mode="fixed_train")` 默认使用保存的训练阈值；`dataset_relative` 重新定义外评集分位目标，只用于评价，不改规则。二者不可混报。显式数值 `cutoff` 也是评价阈值，不会重新学习该阈值对应的规则。
- 保存了 PID 分组的预置模型评价需要同一 ID 约定；不能传 canonical SMILES 代替 PID 后声称无泄漏。`allow_overlap=True` 只能用于明确的重评，不可报告为独立测试。
- 输出 TP/FP/TN/FN、MCC、precision、recall、specificity、F1、coverage、enrichment factor、AS 及阈值/数据角色。不要删掉无效数据集以提高调和分数。
- `model.new_trainer()` 重建训练配方，不复制旧排名或获胜规则。`trainer.export_diagnostics()` 保存相关性、阈值/支持数、候选规则、选择范围指标和模板审计。
- 多个模型可以逐个筛选同一候选；在适配层做结果交集时注明模型、tier 和 AND 条件。没有配对真实性能时，不产生联合精度等真实标签指标。
- 用真实 bit 定义解释规则。MACCS key 可能包含计数或特殊逻辑，不能把每个 key 一律等同于一个无计数 SMARTS 子结构。外层可导出可读生成约束，但上游没有 LLM 训练或分子生成 API。
